# Steps

An accessible step indicator ("stepper" / wizard) for guiding a user through a sequence of steps.

## Import

```ts
import { Steps } from "@kobalte/core/steps";
// or
import {
	Root,
	List,
	Item,
	Trigger,
	Indicator,
	Separator,
	Content,
	CompletedContent,
	Progress,
	NextTrigger,
	PrevTrigger,
} from "@kobalte/core/steps";
// or (deprecated)
import { Steps } from "@kobalte/core";
```

## Features

- A fixed number of steps (`count`), navigated by index.
- Click a step's trigger to jump directly to it, use `NextTrigger`/`PrevTrigger`, or navigate between triggers with the arrow keys (<kbd>Home</kbd>/<kbd>End</kbd> too) — <kbd>Enter</kbd>/<kbd>Space</kbd> commits the navigation.
- Optional `linear` mode: forward navigation is blocked unless the current step is valid (`isStepValid`) — this applies uniformly whether navigation comes from a click or the keyboard.
- Steps can be marked `isStepSkippable`, bypassing them during next/prev navigation.
- A dedicated completed state (`CompletedContent`) once every step is done, announced to assistive technology via `role="status"`.
- A `Progress` part (and a `--percent` CSS variable on the root) for visualizing completion.
- Can be controlled or uncontrolled.
- Horizontal or vertical orientation.
- Built on top of `Tabs` internally, so triggers get `role="tab"`/`aria-selected` and proper roving-tabindex keyboard navigation for free, in addition to Steps-specific `aria-current="step"` and `aria-controls`/`aria-labelledby` linking each trigger to its content.

## Anatomy

The steps component consists of:

- **Steps**: The root container that manages the current step and provides context.
- **Steps.List**: Wrapper for the step items.
- **Steps.Item**: The container for a single step.
- **Steps.Trigger**: A button that navigates directly to the step it belongs to.
- **Steps.Indicator**: A visual marker for a step's status (e.g. its number or a checkmark).
- **Steps.Separator**: A divider between two steps, rendered inside `Steps.Item`.
- **Steps.Content**: The content shown while its associated step is current.
- **Steps.CompletedContent**: The content shown once every step has been completed.
- **Steps.Progress**: A progress bar reflecting how many steps have been completed.
- **Steps.PrevTrigger**: A button that returns to the previous step.
- **Steps.NextTrigger**: A button that advances to the next step.

```tsx
<Steps count={3}>
	<Steps.List>
		{/* one Steps.Item per step */}
		<Steps.Item index={0}>
			<Steps.Trigger>
				<Steps.Indicator />
			</Steps.Trigger>
			<Steps.Separator />
		</Steps.Item>
	</Steps.List>
	<Steps.Content index={0} />
	<Steps.CompletedContent />
	<Steps.Progress />
	<Steps.PrevTrigger />
	<Steps.NextTrigger />
</Steps>
```

## Usage

### Controlled value

The `value` and `onChange` props can be used to make the current step controlled.

:::preview

<ControlledExample />

---

```tsx {3,4,7-9}
import { createSignal } from "solid-js";

function ControlledExample() {
	const [value, setValue] = createSignal(0);

	return (
		<>
			<Steps count={3} value={value()} onChange={setValue}>
				{/* ...list, content... */}
			</Steps>
			<p>Current step index: {value()}</p>
		</>
	);
}
```

:::

### Progress

`Steps.Progress` renders as the fill of a progress bar (sized via `width`) — wrap it in your own track element. The root also exposes a `--percent` CSS variable for custom styling.

:::preview

### Linear mode

Set `linear` to require the steps to be completed in order. Provide `isStepValid` to gate forward navigation — clicking a step's trigger more than one step ahead, or calling `Steps.NextTrigger` while the current step is invalid, is blocked and fires `onStepInvalid` instead. Going backward is always allowed.

:::preview

<LinearExample />

---

```tsx {3-8}
function LinearExample() {
	const [email, setEmail] = createSignal("");

	return (
		<Steps
			count={3}
			linear
			isStepValid={(index) => index !== 0 || email().includes("@")}
			onStepInvalid={() => alert("Enter a valid email first.")}
		>
			<Steps.Content index={0}>
				<input value={email()} onInput={(e) => setEmail(e.currentTarget.value)} />
			</Steps.Content>
			{/* ...remaining steps... */}
		</Steps>
	);
}
```

:::

### Skippable steps

Provide `isStepSkippable` to bypass certain steps when navigating with `Steps.NextTrigger`/`Steps.PrevTrigger`. A skippable step is still reachable by clicking its `Steps.Trigger` directly.

:::preview

<SkippableExample />

---

```tsx {0}
<Steps count={4} isStepSkippable={(index) => index === 2}>
	{/* ...list, content... */}
</Steps>
```

:::

## API Reference

### Steps

`Steps` is equivalent to the `Root` import from `@kobalte/core/steps` (and deprecated `Steps.Root`).

| Prop            | Description                                                                                                                    |
| :--------------- | :------------------------------------------------------------------------------------------------------------------------------ |
| count            | `number` <br/> The total number of steps. **Required.**                                                                        |
| value            | `number` <br/> The controlled index of the current step.                                                                       |
| defaultValue     | `number` <br/> The index of the current step when initially rendered. Useful when you do not need to control the state.        |
| onChange         | `(value: number) => void` <br/> Event handler called when the current step changes.                                            |
| orientation      | `'horizontal' \| 'vertical'` <br/> The orientation of the steps. Defaults to `'horizontal'`.                                     |
| linear           | `boolean` <br/> Whether the user must complete the steps in order. Defaults to `false`.                                        |
| isStepValid      | `(index: number) => boolean` <br/> Returns whether the step at `index` is valid, used to gate forward navigation when `linear` is `true`. Defaults to always `true`. |
| isStepSkippable  | `(index: number) => boolean` <br/> Returns whether the step at `index` should be skipped over by next/prev navigation. Defaults to always `false`. |
| onStepComplete   | `() => void` <br/> Event handler called once when every step has been completed.                                               |
| onStepInvalid    | `(details: { step: number }) => void` <br/> Event handler called when navigation is blocked by an invalid step in `linear` mode. |
| id               | `string` <br/> A unique identifier. Auto-generated if not provided.                                                            |

| Data attribute | Description |
| :--- | :--- |
| `data-orientation` | Reflects the `orientation` prop. |

### Steps.List

Wraps the step items. Internally wraps `Tabs.List`, which is what gives roving-tabindex arrow-key (and <kbd>Home</kbd>/<kbd>End</kbd>) navigation between triggers, along with `role="tablist"` and `aria-orientation`.

No props beyond the common polymorphic/HTML ones.

| Data attribute | Description |
| :--- | :--- |
| `data-orientation` | Reflects the `orientation` prop. |

### Steps.Item

| Prop  | Description                                                             |
| :---- | :------------------------------------------------------------------------ |
| index | `number` <br/> The index of this step. **Required.**                    |

| Data attribute | Description |
| :--- | :--- |
| `data-complete` / `data-current` / `data-incomplete` | Reflects the step's status relative to the current step. |

`Steps.Trigger`, `Steps.Indicator`, and `Steps.Separator` read this status from context — `Steps.Separator` should be rendered as a child of `Steps.Item`, alongside `Steps.Trigger`.

### Steps.Trigger

A button that navigates directly to the step it belongs to. Wraps `Tabs.Trigger` internally, so clicking it (or pressing <kbd>Enter</kbd>/<kbd>Space</kbd> while it's focused) selects it — this is routed through `linear`/`isStepValid` validation before the current step is allowed to change. It also inherits `Tabs.Trigger`'s own `role="tab"`, `aria-selected`, `data-selected`, and `data-highlighted`.

No props beyond the common polymorphic/HTML ones.

`Steps.Trigger` and `Steps.Content` for the same `index` are automatically cross-referenced for assistive technology: `Steps.Trigger` gets `aria-controls` pointing at its `Steps.Content`'s `id`, and `Steps.Content` gets `aria-labelledby` pointing back at the trigger — an `id` is generated for both if you don't provide one yourself. `Steps.Trigger` also sets `aria-current="step"` while it's the current step.

| Data attribute | Description |
| :--- | :--- |
| `data-orientation` | Reflects the `orientation` prop. |
| `data-state` | `"open"` while it's the current step, `"closed"` otherwise. |
| `data-complete` / `data-current` / `data-incomplete` | Reflects the step's status relative to the current step. |

### Steps.Indicator

A visual marker for a step's status (e.g. its number or a checkmark), typically rendered inside `Steps.Trigger`. Renders whatever children you provide — style it using the data attributes below.

No props beyond the common polymorphic/HTML ones.

| Data attribute | Description |
| :--- | :--- |
| `data-complete` / `data-current` / `data-incomplete` | Reflects the step's status relative to the current step. |

### Steps.Separator

A purely decorative divider between two steps, rendered as a child of `Steps.Item`, reflecting the status of the step it follows. Hidden from assistive technology (`aria-hidden="true"`), matching `Breadcrumbs.Separator`. Typically hidden visually after the last item via a `:last-child` CSS rule.

No props beyond the common polymorphic/HTML ones.

| Data attribute | Description |
| :--- | :--- |
| `data-complete` / `data-current` / `data-incomplete` | Reflects the step's status relative to the current step. |

### Steps.Content / Steps.CompletedContent

| Prop         | Description                                                                                                                              |
| :----------- | :--------------------------------------------------------------------------------------------------------------------------------------- |
| index        | `number` <br/> (`Steps.Content` only) The index of the step this content belongs to. **Required.**                                       |
| `forceMount` | `boolean` <br/> Used to force mounting when more control is needed. Useful when controlling animation with SolidJS animation libraries. |

| Data attribute | Description |
| :--- | :--- |
| `data-current` | (`Steps.Content` only) Present while its associated step is the current one. |

`Steps.CompletedContent` renders with `role="status"` (a polite live region) — completing a wizard is a positive, non-urgent update rather than an error, so `status` is used instead of the more disruptive `alert`.

### Steps.NextTrigger / Steps.PrevTrigger

Buttons that advance to the next step or return to the previous one. `Steps.NextTrigger` is subject to `linear`/`isStepValid`/`isStepSkippable`. Both wrap `Button.Root`; `onClick` is composed with the built-in navigation handler rather than replaced by it.

No props beyond the common polymorphic/HTML ones (plus `onClick`).

`Steps.NextTrigger` is `disabled` when `hasNextStep` is `false`; `Steps.PrevTrigger` is `disabled` when `hasPrevStep` is `false`.

### Steps.Progress

A progress bar reflecting how many steps have been completed. Renders as the fill itself (sized via a `width` style based on `percent`) — wrap it in your own track element.

No props beyond the common polymorphic/HTML ones.

| Data attribute | Description |
| :--- | :--- |
| `data-complete` | Present once every step has been completed. |

`Steps.Progress` renders with `role="progressbar"`, `aria-valuenow` (the current step index), `aria-valuemin={0}`, and `aria-valuemax` (the step count).

### useStepsContext

Returns the `StepsContextValue` object. Must be called inside a `Steps`. Used to build custom sub-components, or to drive navigation programmatically.

| Property        | Type                                        | Description                                                    |
| :-------------- | :------------------------------------------- | :--------------------------------------------------------------- |
| value           | `Accessor<number>`                           | The index of the current step (equals `count` once completed).  |
| count           | `Accessor<number>`                           | The total number of steps.                                       |
| percent         | `Accessor<number>`                           | The completion percentage, between 0 and 100.                    |
| hasNextStep     | `Accessor<boolean>`                          | Whether there is a step after the current one.                   |
| hasPrevStep     | `Accessor<boolean>`                          | Whether there is a step before the current one.                  |
| isCompleted     | `Accessor<boolean>`                          | Whether every step has been completed.                            |
| isStepValid     | `(index: number) => boolean`                 | Returns whether the step at `index` is valid.                     |
| isStepSkippable | `(index: number) => boolean`                 | Returns whether the step at `index` should be skipped over by next/prev navigation. |
| getItemState    | `(index: number) => "complete" \| "current" \| "incomplete"` | Returns the current status of the step at `index`. |
| canChangeStep   | `(index: number) => boolean`                 | Returns whether navigating directly to `index` is currently allowed. |
| changeStep      | `(index: number) => void`                    | Navigates to `index` if `canChangeStep(index)`, otherwise fires `onStepInvalid`. |
| setStep         | `(index: number) => void`                    | Directly sets the current step, clamped to `[0, count]`. Not subject to `linear` validation. |
| goToNextStep    | `() => void`                                 | Advances to the next (non-skipped) step, subject to `linear` validation. |
| goToPrevStep    | `() => void`                                 | Returns to the previous (non-skipped) step.                       |
| resetStep       | `() => void`                                 | Resets to the first step.                                         |

## Accessibility

### Keyboard Interactions

`Steps.Trigger` always uses manual activation: the arrow keys (and <kbd>Home</kbd>/<kbd>End</kbd>) only move roving focus between triggers, they never change the current step on their own — appropriate for a step wizard, where focusing the next trigger to "just look" at it shouldn't silently advance the stepper. <kbd>Enter</kbd>/<kbd>Space</kbd> commits the navigation, subject to `linear`/`isStepValid` validation.

| Key                   | Description                                                                                                                   |
| :--------------------- | :------------------------------------------------------------------------------------------------------------------------------ |
| <kbd>Tab</kbd>        | Moves focus to the first (or last active) trigger. Once focused, arrow keys navigate the remaining triggers.                  |
| <kbd>ArrowDown</kbd>  | Moves focus to the next trigger in vertical orientation.                                                                       |
| <kbd>ArrowRight</kbd> | Moves focus to the next trigger in horizontal orientation.                                                                     |
| <kbd>ArrowUp</kbd>    | Moves focus to the previous trigger in vertical orientation.                                                                   |
| <kbd>ArrowLeft</kbd>  | Moves focus to the previous trigger in horizontal orientation.                                                                 |
| <kbd>Home</kbd>       | Moves focus to the first trigger.                                                                                              |
| <kbd>End</kbd>        | Moves focus to the last trigger.                                                                                               |
| <kbd>Enter</kbd>      | Navigates to the focused trigger's step, subject to `linear`/`isStepValid` validation.                                         |
| <kbd>Space</kbd>      | Navigates to the focused trigger's step, subject to `linear`/`isStepValid` validation.                                         |
