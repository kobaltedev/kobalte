## v2.0.0

**Breaking changes**

- **Solid 2.0 is now required.** Peer dependencies are `solid-js@^2.0.0` and `@solidjs/web@^2.0.0`. Solid 1.x is no longer supported.
- The JSX import source has changed from `solid-js` to `@solidjs/web`. Update your `tsconfig.json`:
  ```json
  { "compilerOptions": { "jsxImportSource": "@solidjs/web" } }
  ```
- `JSX` namespace types and DOM-specific component types must now be imported from `@solidjs/web` instead of `solid-js`.
- Context providers now use the `value` prop directly — `<Context.Provider value={...}>` is replaced by `<Context value={...}>`.
- DOM attributes passed to Kobalte parts use Solid 2.0's lowercase convention: `tabindex`, `inputmode`, `autocomplete`, `spellcheck`, `contenteditable`, `readonly`.
- Import each component from its own entry point (`@kobalte/core/dialog`, `@kobalte/core/tabs`, ...). The package root `@kobalte/core` is no longer an export, and `src/` is no longer shipped.
- `Dialog`, `Tabs`, etc. are the Root component with the other parts attached (`Dialog.Trigger`, `Dialog.Content`, ...). The `Dialog.Root` alias is gone: use `Dialog` or the `Root` named export.
- Solid 2.0's `merge` keeps explicitly passed `undefined` values, so `id={undefined}` or `shouldFocusWrap={undefined}` no longer falls back to the component default. Omit the prop to get the default.
- `createTransition` was removed, it is superseded by Solid 2.0's built-in transition model.
- `@solidjs/testing-library@1.0.0-rc.2` is the only release compatible with Solid 2 if you test Kobalte components.

**Migrating your own code**

Kobalte itself no longer needs changes beyond the list above. Your application code needs the Solid 1 to Solid 2 changes from Solid's own 2.0 migration guide: `@solidjs/web` imports, split `createEffect`, `merge`/`omit` replacing `mergeProps`/`splitProps`, `<Loading>`/`<Errored>` replacing `<Suspense>`/`<ErrorBoundary>`, and `<Index>` replaced by `<For keyed={false}>` (or `<Repeat>` for a fixed count).

**New features**

- [New `Drawer` component](/docs/core/components/drawer) — a panel that slides in from any edge of the screen with drag-to-dismiss, snap-point support, and real-time overlay opacity tracking. Adapted from [corvu/drawer](https://github.com/corvudev/corvu/tree/main/packages/drawer) by Jasmin Noetzli (MIT).
- [New `Resizable` component](/docs/core/components/resizable) — a set of panels that can be resized by dragging the handles between them. Supports horizontal and vertical layouts, collapsible panels, pixel or fraction sizes, nested layouts, and full keyboard navigation. Adapted from [corvu/resizable](https://github.com/corvudev/corvu/tree/main/packages/resizable) by Jasmin Noetzli (MIT).
- [New `OTPField` component](/docs/core/components/otp-field) — an accessible one-time password input built from a hidden native `<input>` and fully customisable visual slots. Supports autofill, custom character patterns, caret tracking, and Kobalte's standard form control system.
- [New `DateField` component](/docs/core/components/date-field) — a segmented date/time input with per-segment keyboard editing and Kobalte's standard form control system. Values are native `Date` objects (Gregorian only, no explicit per-value time zone).
- [New `Calendar` component](/docs/core/components/calendar) — a date grid supporting single, multiple, and range selection and full keyboard navigation, built on native `Date`. Range selection follows [corvu/calendar](https://github.com/corvudev/corvu/tree/main/packages/calendar)'s click-only model (first click sets the start, second click commits the end — no pointer-drag) by Jasmin Noetzli (MIT).
- [New `Steps` component](/docs/core/components/steps) — a step indicator for multi-step flows with per-step validity and skippable steps.
- [New `Statistic` component](/docs/core/components/statistic) — displays a labeled numeric value such as a KPI or dashboard metric, with locale formatting and trend indicator.
- [New `Card` component](/docs/core/components/card) and [`Divider` component](/docs/core/components/divider).
- [New `DatePicker` component](/docs/core/components/date-picker) — a trigger button that opens a `Calendar` in a `Popover` to pick a date, dates, or date range. corvu has no dedicated date-picker primitive; this follows [its own suggested composition](https://corvu.dev/docs/primitives/calendar/) of `Calendar` directly inside `Popover`.
- `DateField`/`Calendar`/`DatePicker` intentionally do not depend on [`@internationalized/date`](https://react-spectrum.adobe.com/internationalized/date/) — this trades away three capabilities in exchange for zero extra runtime dependencies: no non-Gregorian calendar systems (Gregorian only, permanently), no explicit per-value time zone or DST-safe arithmetic (all date math runs in the browser's local time zone), and no era segment in `DateField` (no calendar-system era concept to expose).

**Solid Primitives integration**

Internal primitives have been replaced with their `@solid-primitives` equivalents, reducing the custom code surface and aligning with the broader Solid ecosystem:

- `createControllableSignal` → `@solid-primitives/controlled-signal`
- `createFormResetListener` → `@solid-primitives/form`
- `createSize` / `createElementSize` → `@solid-primitives/resize-observer`
- Reduced-motion detection → `@solid-primitives/media` (via interaction)
- Presence/exit animation management → `@solid-primitives/presence`
- i18n utilities → `@solid-primitives/i18n`
- Keyboard shortcut tracking → `@solid-primitives/keyboard`
- `combineStyle` / prop utilities → `@solid-primitives/props`
- Scroll locking → `@solid-primitives/scroll`
- A11y helpers → `@solid-primitives/a11y`
- Focus management → `@solid-primitives/focus`

**Internal changes**

- All components ported to the Solid 2.0 API: split `createEffect(compute, apply)` form, `omit` replacing `splitProps`, `merge` replacing `mergeProps`, auto-batched writes, and `<Loading>` / `<Errored>` replacing `<Suspense>` / `<ErrorBoundary>` in internal use.
- `createTransition` removed — superseded by Solid 2.0's built-in transition model.
- TypeScript updated to 7.0 with stricter type checking applied across all components.
- Biome updated to 2.5.15 for formatting and linting.
- pnpm updated to 11.
- Vite updated to 8, Vitest to 5, and Storybook to 10.
- `@solidjs/testing-library` updated to 1.0.0-rc.2.
